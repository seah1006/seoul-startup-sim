# 리뷰 기준 (REVIEW_GUIDE)

작업 브랜치를 main에 합치기 전에 두 단계 리뷰를 돌린다. 1단계는 이 문서를 기준으로 보고, 2단계는 이 문서를 보여 주지 않은 다른 모델이 맥락 없이 본다. 결과는 아래 세 등급으로 정리한다.

| 등급 | 뜻 | 처리 |
|---|---|---|
| **P0 반드시** | 데이터 손상, 보안, 재현성 깨짐, 실서비스 오류, 이 문서의 "절대 규칙" 위반 | 합치기 전에 고친다 |
| **P1 고치면 좋음** | 버그 가능성, 경계값, 테스트 빈 곳, 성능 저하, 계약(API) 불일치 | 이번에 고치거나 이유를 남기고 다음 작업으로 |
| **P2 찜찜함** | 가독성, 이름, 중복, 취향 | 기록만. 사람이 판단 |

## P0: 절대 규칙
1. **비밀값**: API 키·비밀번호·토큰이 코드, 문서, 테스트, 커밋, 로그 출력에 없다. `.env`는 커밋되지 않는다.
2. **재현성**: 시드 + 선택 + 데이터 버전이 같으면 결과가 같다. 골든 테스트 파일(`backend/src/test/resources/**golden**`)을 바꾸는 변경은 지시서에 승인 근거가 있어야 한다. 새 난수는 기존 `EventRandom` 스트림과 분리된 이름을 쓴다.
3. **Flyway**: 이미 배포된 마이그레이션(V1~현재 배포본)은 수정하지 않는다. 새 파일만 추가하고 버전 순서를 지킨다(`outOfOrder=false`).
4. **데이터 버전 보존**: 분기 참조 테이블은 덮어쓰지 않고 새 버전으로 넣는다. 게임은 생성 시 고정된 버전(pins)만 읽는다.
5. **게임 중 외부 API 금지**: 게임 요청 경로에서 외부 API를 부르지 않는다. 외부 데이터는 배치 수집 → DB.
6. **서버 권위**: 게임 판정·금액·확률은 서버가 계산한다. 클라이언트가 보낸 결과값을 믿지 않는다.
7. **실제 상호**: 실제 가게 상호·브랜드·실존 인물은 사실 정보(경쟁 점포 목록 등)에만. 가상 사건·반응 문구에 쓰지 않는다.
8. **권한**: 회원 전용 쓰기(게시판), 소유자 전용 게임 조회·수정, 관리자 화면 보호가 유지된다. 게스트 토큰으로 다른 사람 게임을 조작할 수 없다.
9. **동시성·멱등**: 분기 진행·선택·매각은 버전 검사와 `Idempotency-Key`를 지킨다. 같은 요청이 두 번 반영되지 않는다.

## P1: 자주 생긴 문제
- **API 계약 불일치**: `docs/api/API_CONTRACT.md`와 실제 응답 필드명·null 처리·에러 코드가 다르다. 프론트 목 데이터(`frontend/src/api/mock`)와 실제 응답이 다르다.
- **실데이터 정직성**: 단위를 모르는 값(예: 길단위인구)을 절대값처럼 보여 준다. 추정치를 실측처럼 표시한다. 데이터가 null일 때 0으로 바꿔 보여 준다.
- **사건 콘텐츠**: 효과 라벨과 실제 효과 수치가 다르다. 공짜 정답 선택지. 조건이 null 데이터에서 참이 된다. 체인 FLAG가 지워지지 않아 반복된다.
- **밸런스**: 식품 업종 표준 정책 생존율이 41~75%를 벗어난다. 목표 달성률이 0% 또는 90% 이상.
- **표시 형식**: 금액이 "1,383만 원" 규칙과 다르다. 숫자에만 mono 글꼴. 조사 치환(`{shopName:이/가}`) 누락.
- **접근성·모바일**: 390px 가로 넘침, 터치 영역 44px 미만, 버튼·입력의 접근성 이름 변경으로 테스트가 깨짐.
- **테스트**: 새 분기·새 등급·새 에러 경로에 테스트가 없다. 테스트를 지우거나 기대값만 바꿔 통과시켰다.
- **배포 메모리**: 1GB 서버 기준 JVM·DB 제한(앱 520MiB, DB 300MiB)을 넘길 수 있는 쿼리·캐시.

## P2
- 이름, 주석, 중복 코드, 파일 길이, 문구 다듬기.

## 리뷰 결과 형식
```
[P0] 파일:줄 — 문제 한 줄
  근거: 코드/동작 설명
  제안: 고치는 방법
```
결과는 `docs/reviews/REVIEW-<번호>.md`에 남긴다.

## 1. 인증 화면 (계약 5장, 목 우선)
- API 레이어: 모든 요청을 `Authorization: Bearer`로 보낸다(백엔드가 `X-Guest-Token`도 받지만 새 방식으로 통일). 토큰 저장 키는 하나(게스트·회원 공용), 로그인·가입 성공 시 교체, 로그아웃 시 삭제 후 새 게스트 발급은 **게임을 시작할 때만**.
- 401: 저장 토큰 삭제 → (게임 화면이면) 게스트 재발급 1회 / (회원 화면이면) 로그인 페이지로. 403 `MEMBER_REQUIRED`: "로그인이 필요해요" 안내 + 로그인/가입 버튼.
- 화면
  - `/login`: 아이디, 비밀번호, 오류 문구(실패 같은 메시지, 423 잠금 안내), 가입 링크, 로그인 후 원래 위치로 복귀(`?next=`)
  - `/signup`: 아이디·닉네임·비밀번호·비밀번호 확인, 클라이언트 검증(계약 규칙 그대로), 409 필드별 오류. **게스트로 플레이 중이면 "지금 게임 기록을 그대로 가져가요" 안내**
  - `/me`(내 계정): 내 정보, 닉네임 수정, 비밀번호 변경(성공 시 "다른 기기에서 로그아웃됐어요"), 탈퇴(비밀번호 확인 + 확인 대화상자)
  - 헤더: 로그인 상태(닉네임, 내 계정, 로그아웃) / 게스트(로그인, 가입)
- 게시판 쓰기 버튼·댓글 입력·좋아요·신고: 게스트면 비활성 대신 "로그인하고 참여하기"로 안내. 엔딩의 "엔딩 인증하기"도 회원만(게스트면 가입 유도, 가입 후 같은 화면 복귀)
- 목: 회원 저장소(아이디·닉네임 중복, 5회 실패 잠금, 게스트 전환 시 같은 userId) 결정론적으로

## 2. QA-1 지적 수정
- 중간 1: 목 모드에서 공유 페이지(`/share/{id}`) 링크가 500 → 목 모드에서는 "공유 페이지는 서버 연결 시 열려요" 안내(링크 비활성) 또는 목 공유 미리보기 화면
- 중간 2: RECORD 필터의 업종·상권 코드 직접 입력 → 업종은 `/api/industries` 선택 목록, 상권은 이름 검색(`/api/areas/search`) 자동완성으로 코드 선택
- 중간 3: 잘못된 gameId로 RECORD 작성 진입 시 "서버 연결 실패" 대신 404 → "인증할 게임을 찾을 수 없어요", 409 → "아직 끝나지 않은 게임이에요"
- 중간 4: 목 게시글 `isMine`이 작성자와 불일치 → 목 데이터는 현재 사용자 기준으로 계산
- 낮음: 404 페이지 안내 문구, 결산·기록 화면의 분기 코드 `20231` → "2023년 1분기", 랭킹 날짜 변경 시 목 필터링

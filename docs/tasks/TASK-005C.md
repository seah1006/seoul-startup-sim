## 할 것
1. **게시판 API 어댑터 (리뷰 I8)**: 기존 `client.ts`의 게임 요청 동작은 바꾸지 않는다. 게시판 요청용 함수를 따로 두고
   - 인증 모드 `none`(목록) / `optional`(상세, 댓글 목록: 저장된 토큰이 있으면 보내되 **자동 발급하지 않음**) / `required`(쓰기: 토큰이 없으면 기존 게스트 발급 흐름)
   - `204`는 본문 파싱 없이 성공 처리
   - 오류는 `ApiError`에 `status`, `code`, `message`를 모두 보존 (같은 409라도 `POST_VERSION_CONFLICT`, `ALREADY_REPORTED` 등을 코드로 분기)
   - 목과 실제 응답이 같은 모양(204, 409 코드 포함)이 되게 목도 맞춘다.
2. 타입: 계약 4장 요청·응답을 `api/types.ts`에 추가(`PageResponse<T>`, `PostListItem`, `PostDetail`, `RecordSnapshot`, `CommentItem` 등), 에러 코드 문자열 유니온.
3. 화면
   - `/board` 목록: 카테고리 탭(전체/자유/공략/질문/엔딩 인증), 정렬(최신/인기/조회/댓글), 검색(검색 종류 + 입력), RECORD 탭에서만 업종·상권 필터, 고정 글 표시, 페이지네이션, 빈 목록 안내. 쿼리스트링과 상태 동기화(뒤로 가기 유지).
   - `/board/posts/:postId` 상세: 본문 텍스트 렌더링(HTML 해석 금지, 줄바꿈 유지), RECORD 카드(엔딩 종류, 업종, 상권, 생존 분기, 누적 순이익, "공유 카드 보기" → `record.shareUrl`), 좋아요(낙관적 반영 후 실패 시 되돌림, 요청 직렬화), 수정·삭제(`isMine`일 때만), 신고(사유 선택 모달).
   - 댓글: 루트 페이징 + "답글 N개 보기"로 대댓글 페이징, 작성·수정·삭제, 자리표시자 표시, 대댓글에는 답글 버튼 없음.
   - `/board/write`, `/board/posts/:postId/edit`: 카테고리, 제목(100자), 본문(10000자) 글자 수, 클라이언트 검증 + 서버 400 메시지. 제출 중 버튼 잠금. 409 `POST_VERSION_CONFLICT`면 "다른 곳에서 수정됨, 최신 내용 불러오기". 429면 "잠시 후 다시 시도".
   - RECORD 작성은 **엔딩 화면에서만 진입**(`?category=RECORD&gameId=…`). 일반 작성 화면의 카테고리 목록에는 RECORD를 넣지 않는다(내 종료 게임 목록 API가 없으므로 의도적 축소). 진입 시 3장 summary로 엔딩 카드 미리보기 + "카드 값과 이름이 공개됩니다" 안내(005B 전에는 목).
   - 내 글 `/board/me`: 상태(숨김) 배지, 숨김 글은 상세 링크 없음.
4. 진입점: 홈에 인기글 3건(`sort=popular&size=3`), 엔딩 화면에 "엔딩 인증하기"(공개 인증글이 있으면 "인증글 보기"), 상단 메뉴 "커뮤니티".
5. 금액 표기는 TASK-004C 공통 포맷 함수 재사용.

## 테스트 (기존 프론트 테스트 방식)
- 어댑터: 204 성공 처리, 409 코드 보존, optional 모드에서 토큰 자동 발급 안 함
- 목록 쿼리스트링 ↔ 상태, RECORD 탭에서만 필터 표시
- 본문에 `<script>` 문자열이 있어도 텍스트로 보임
- 댓글: 대댓글에 답글 버튼 없음, 자리표시자 렌더링, 삭제 후 목록 갱신
- 글 삭제 후 목록으로 이동하고 해당 글이 사라짐
- 좋아요 실패 시 롤백, 409·429 안내, 401이면 게스트 시작 유도

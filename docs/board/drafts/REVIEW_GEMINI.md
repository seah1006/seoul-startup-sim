## 3. 채점자 예상 질문 방어 & 차별점 3가지

### Q. "싱글 창업 게임인데 왜 게시판을 넣었나요?"
> "싱글 플레이 게임이지만 다른 사장님들과의 전략 비교와 회고가 핵심 재미이기 때문에, 숫자만 나열되는 랭킹을 넘어 공략과 엔딩 후기를 나누는 커뮤니티를 결합했습니다. 특히 단순 자유게시판에 그치지 않고, 종료된 게임의 실제 상권·업종·수익 데이터를 서버가 직접 검증해 스냅샷으로 박제하는 `RECORD(엔딩 인증글)`와 Thymeleaf 공유 페이지(`/share/{gameId}`)를 연결해 플레이가 끝난 뒤에도 서비스 안에서 소비와 공유가 순환하도록 설계했습니다. 이를 통해 Spring Boot 백엔드의 페이징, 동적 검색, 낙관적 락, 동시성 제어, 권한 분리와 Thymeleaf PRG까지 기말 핵심 평가 요소를 하나의 도메인 안에 자연스럽게 녹여냈습니다."

### 남들 커뮤니티 과제 대비 차별점 3가지
1. **게임 상태 기반 서버 검증 & 위변조 불가 스냅샷 (`RECORD`)**: 요청에는 `gameId`만 받고, 소유권(`403`)·종료 상태(`409`)를 서비스와 DB 트리거(`trg_posts_record_game_guard`)로 이중 검증한 뒤 업종·상권·수익 요약을 서버 원본에서 복사해 위조를 원천 차단한다.
2. **한국어 상권 검색 최적화(`pg_trgm` + GIN) & 도메인 교차 필터**: `LIKE` 풀스캔 대신 `pg_trgm` GIN 인덱스를 적용하고 `EXPLAIN`으로 인덱스 사용을 검증했으며, 실제 서울시 상권코드(`areaCode`)와 업종코드(`serviceCode`) 기반 필터링을 제공한다.
3. **동시성·정합성 엔지니어링과 목적별 하이브리드 아키텍처**: 멱등 좋아요(`PUT`/`DELETE` + 실제 반영 행 수 기반 카운터), `version` 낙관적 락(`409`), KST 1일 1회 조회수 중복 방지(`post_views`), 1단계 대댓글 DB 트리거 및 자리표시자, 그리고 React REST(사용자 SPA) + Thymeleaf Spring Security PRG(관리자/공유)의 역할 분리를 모두 구현했다.

## 4. 일정 리스크: TASK-005B의 엔딩 작업 의존성 & 대안

- **리스크**: `TASK-005B`는 엔딩·랭킹 작업(`GET /api/games/{gameId}/summary`, `game_records`, `/share/{gameId}`)이 `main`에 병합되어야 시작 가능. 발표 전까지 엔딩 작업이 끝나지 않으면 `RECORD` 작성과 공유 페이지 연결 시연이 막힘.
- **발표 전 미완료 시 단계별 대안**:
  1. **1차 대안 (005A + 005C만으로 평가 항목 100% 방어)**:
     - `TASK-005A`는 `game` 패키지 의존 없이 독립 완결되므로, `TIP`/`FREE`/`QNA` 카테고리로 페이징·검색·정렬·`@Valid` 400·수정 409·댓글/대댓글·멱등 좋아요·신고·관리자 Thymeleaf PRG·Soft Delete까지 **백엔드 평가 체크리스트 Must/Should 전 항목을 라이브 시연**한다.
     - `DEMO_SCENARIO.md`의 `1:40-2:40` 구간은 **"일반 `TIP` 글 작성 + `@Valid` 400 검증"**으로 대체하고, `TASK-005C`의 **목(mock) 모드**로 엔딩 카드 미리보기와 인증글 UI를 보충 시연한다.
  2. **2차 대안 (DB 시드 우회로 `RECORD` 조회·필터까지 라이브 시연)**:
     - `V11__board.sql`에 이미 `RECORD` 스냅샷 컬럼과 트리거가 있으므로, `seed_board_demo.sql`에 더미 `ENDED` 게임과 `RECORD` 게시글을 함께 적재하면 **목록의 `RECORD` 탭 필터(`serviceCode`, `areaCode`)와 상세의 엔딩 카드 조회**까지는 백엔드 라이브로 시연할 수 있다(작성 API만 400 차단 유지).
  3. **설계 방어 멘트**:
     - "`game` 도메인과의 결합도를 낮추기 위해 `BoardRecordReadRepository` 읽기 포트로 격리했고, DB 트리거·부분 유일 인덱스·프론트 목 화면까지 선행 구현해 엔딩 작업이 병합되는 즉시 스위치만 열면 연동되는 구조입니다."

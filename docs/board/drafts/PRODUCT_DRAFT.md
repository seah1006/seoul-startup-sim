## 1. Spring 백엔드 실습 평가 체크리스트

일반적인 Spring Boot 백엔드 실습 과제(커뮤니티/쇼핑몰)에서 채점자가 확인하는 핵심 평가 항목과 본 프로젝트의 우선순위(`Must` / `Should` / `Nice`)입니다.

| 영역 | 평가 항목 | 등급 | 본 프로젝트 구현 기준 |
| --- | --- | --- | --- |
| **기본 CRUD** | 목록 조회 + 페이징(`Pageable`) | **Must** | `page`, `size`, `sort` 파라미터 기반 페이지네이션 및 전체 건수/페이지 메타 반환 |
| | 다중 정렬 | **Must** | `latest`(최신순), `popular`(좋아요순), `views`(조회수순), `comments`(댓글순) 지원 + 공지(`isPinned`) 상단 우선 노출 |
| | 다중 조건 검색 & 필터 | **Must** | 검색 타입(`title`, `content`, `titleContent`, `author`) + 카테고리(`FREE`, `TIP`, `QNA`, `RECORD`) + 게임 연동 필터(`areaCode`, `serviceCode`) |
| | 상세 조회 + 조회수 증가 | **Must** | 단건 조회 시 `viewCount` 증가(삭제/숨김 글 404 처리) |
| | 작성 + 입력값 검증(`@Valid`) | **Must** | DTO Bean Validation(`@NotBlank`, `@Size`, `@NotNull`), 실패 시 `400 VALIDATION_FAILED` 반환 |
| | 수정 + 낙관적 락(`version`) | **Must** | 작성자 본인만 수정 가능(`403`), `expectedVersion` 불일치 시 `409` 충돌 응답으로 동시 수정 방지 |
| | 삭제(Soft Delete) | **Must** | `deleted_at` 기록(작성자 또는 관리자만 가능). 댓글이 달린 원글/대댓글이 있는 부모 댓글 처리 규칙 명확화 |
| **연관/상호작용** | 댓글 + 대댓글(1단계) | **Must** | `parent_id` 자기참조. 2단계 이상 대댓글 시도 시 `400` 차단. 자식 댓글이 있는 부모 삭제 시 "삭제된 댓글입니다" 마스킹 |
| | 좋아요(추천) + 동시성 | **Must** | 사용자당 1회 제한(`UNIQUE(post_id, user_id)`), 취소 가능. `PUT`/`DELETE` 멱등 API로 네트워크 재시도 시 상태 반전 방지 |
| **인증·인가** | 소유권 검증 & 권한 분리 | **Must** | 일반 사용자: `X-Guest-Token` (`GuestAuth.resolve()`)로 `user_id` 판별(비인증 `401`, 타인 글 수정/삭제 `403`). 관리자: Spring Security 세션(`ROLE_ADMIN`) |
| **예외·트랜잭션** | 전역 예외 처리 일관성 | **Must** | `@RestControllerAdvice` 기반 `{code, message, timestamp}` 공통 JSON 에러 포맷 준수 |
| | `@Transactional` 경계 | **Must** | 글/댓글/좋아요 카운트 갱신, 신고 처리, `RECORD` 스냅샷 저장 등 원자성 보장 |
| **REST 설계** | HTTP 메서드·상태코드·네이밍 | **Must** | 복수형 리소스(`/api/board/posts`), 적절한 상태코드(`200`, `201`, `204`, `400`, `401`, `403`, `404`, `409`), camelCase JSON |
| **테스트** | 통합/단위 테스트 | **Must** | JUnit 5 + Testcontainers(PostGIS) 기반 CRUD, 권한 `403`, 낙관적 락 `409`, 중복 좋아요 방지, `RECORD` 게임 소유/종료 검증 테스트 |
| **운영·신고** | 신고 & 관리자 블라인드 | **Should** | 사용자 중복 신고 방지(`UNIQUE`) + `/admin/board`에서 신고 목록 확인 후 숨김(`is_hidden`)/해제 처리 |
| | 공지 상단 고정 | **Should** | 관리자 권한으로 게시글 `is_pinned` 토글. 기존 `notices`(게임 패치노트)와 역할 분리 |
| **Spring MVC** | Thymeleaf + Form/PRG | **Should** | 관리자 화면(`/admin/board/**`)에서 `@Controller` + Thymeleaf 폼 바인딩 + `BindingResult` 검증 + PRG(Post-Redirect-Get) 패턴 시연 |
| **부가 기능** | 조회수 중복 증가 방지 | **Nice** | 동일 사용자/세션 짧은 시간 내 중복 조회수 증가 방지(MVP에서는 단순 증가도 허용, 시간 여유 시 추가) |
| | 이미지 파일 업로드 | **Nice** | 스토리지·보안 검증 비용 대비 시연 효율이 낮아 **MVP 제외(Later)** |

## 2. 게임 연동 기능 목록 및 A/B/C 결정

### 2-1. (A) 사장님 커뮤니티 & `RECORD`(엔딩 인증글)

1. **카테고리 구성 (4종)**
   - `FREE` (자유): 창업 잡담, 상권 이야기
   - `TIP` (공략): 업종별 운영 노하우, 전환점 공략
   - `QNA` (질문): 상권 선택, 스탯 육성 질문
   - `RECORD` (엔딩 인증글): 실제 플레이한 엔딩 결과를 첨부해 자랑·회고하는 핵심 차별화 카테고리
   - *공지(`notices` 테이블과의 관계)*: 기존 `notices` 테이블은 **게임 서비스 공지/패치노트**(홈 화면 노출) 용도로 유지하고, 게시판 내 상단 고정 안내는 게시글의 `is_pinned` 플래그(관리자 전용 설정)로 처리해 테이블 역할 충돌을 피한다.

2. **`RECORD` 엔딩 인증글 규칙 (확정)**
   - **작성 자격**: `game.user_id == currentUserId` 인 **본인 소유 게임**만 첨부 가능 (타인 게임 첨부 시 `403 FORBIDDEN`).
   - **게임 상태**: `game.status == 'ENDED'` 인 **종료된 게임**만 첨부 가능 (진행 중 `PLAYING` 게임 첨부 시 `400` 또는 `409 GAME_NOT_ENDED`).
   - **중복 인증 정책 (게임당 활성 글 1개 제한)**:
     - 같은 `game_id`로 삭제되지 않은(`deleted_at IS NULL`) `RECORD` 글은 **1개만** 허용한다. (이미 존재하면 `409 RECORD_ALREADY_EXISTS`).
     - 단, 작성자가 기존 인증글을 삭제(`deleted_at` 기록)한 뒤 다시 작성하는 것은 허용한다(DB 부분 유니크 인덱스 `WHERE category = 'RECORD' AND deleted_at IS NULL` 활용). → 시연 중 실수로 삭제해도 재시연이 가능하며, 랭킹/공유 페이지와 1:1 연결이 깔끔하게 유지된다.
   - **엔딩 스냅샷 저장**:
     - `RECORD` 글 작성 시점에 `games`, `owners`, `shops`, `game_records`를 읽기 전용으로 조회해 엔딩 요약 정보를 게시글에 스냅샷으로 저장한다.
     - 저장 항목: `gameId`, `endingType`(`CLOSED|SOLD|LONG_RUNNING`), `ownerName`, `shopName`, `areaCode`, `areaName`, `serviceCode`, `serviceName`, `survivedQuarters`, `totalProfit`(원 단위 `long`), `bestQuarterProfit`.
     - 이 중 `areaCode`, `serviceCode`, `endingType`, `survivedQuarters`, `totalProfit` 등은 목록 필터링(`areaCode`, `serviceCode`)과 카드 배지 렌더링에 즉시 활용할 수 있도록 별도 컬럼 또는 인덱스 가능한 구조로 둔다.
   - **수정 제한**: `RECORD` 글의 `title`, `content`는 수정 가능하지만, 첨부된 `gameId`와 엔딩 스냅샷은 변조 방지를 위해 수정 불가.

### 2-2. (B) 엔딩 공유 페이지(`/share/{gameId}`) 연결 — **MVP 포함**

- `GET /share/{gameId}` (Thymeleaf) 렌더링 시, 해당 `gameId`로 작성된 활성 `RECORD` 게시글이 있는지 조회한다.
- **연결 방식**:
  - 인증글이 있으면: 공유 페이지 하단에 **"사장님 인증글 보러가기"** 카드(제목, 좋아요 수, 댓글 수, React 상세 페이지 링크 `/board/posts/{postId}`)를 노출한다.
  - 인증글이 없으면: 공유 페이지 자체는 정상 표시하되, 인증글 작성 안내 문구(예: "아직 작성된 엔딩 인증글이 없습니다")를 노출한다.
- **효과**: 서버 렌더링(Thymeleaf) 공유 페이지와 React 커뮤니티가 자연스럽게 이어져, 단절된 두 화면이 아닌 하나의 서비스 흐름으로 보인다.

### 2-3. (C) 동네 반응(`turn_results.reactions`) 답글 — **MVP 제외 (Later로 분리)**

- **판단**: **MVP에서 제외하고 추후 확장(Later)**으로 둔다.
- **이유**:
  1. 현재 `game` 패키지는 `TASK-004A` 리팩터링 중이므로 수정 금지 제약이 있다.
  2. 기말까지 남은 핵심 게임 작업(전환점, 엔딩/랭킹, 카카오 로그인, 배포)과 게시판 기본 CRUD 완성도를 먼저 확보해야 한다.
  3. 동네 반응 답글에 게임 효과를 붙이면 분기 계산 로직(`QuarterCalculator`)과 `game` 도메인 상태를 건드려야 한다.
- **추후(Later) 도입 시 게임 결정론 유지 설계안**:
  - 본 프로젝트 원칙은 **"시드 + 플레이어 선택 + 데이터 버전이 같으면 결과가 동일해야 한다"**이다.
  - 따라서 사장님이 동네 반응에 자유 텍스트로 답글을 달더라도, **텍스트 자체를 LLM/키워드로 해석해 효과를 주면 결정론이 깨진다.**
  - 대신 답글 작성 시 **"대응 태도 선택지(Choice)"**를 함께 고르게 한다:
    - 예: `THANK`(감사 인사 → 단골 전환 소폭 보정), `COUPON`(할인 쿠폰 약속 → 다음 분기 방문객 보정 + 마케팅비 소액 차감), `IMPROVE`(개선 약속 → 서비스 판정 보정).
  - 이 선택을 `reaction_replies(game_id, turn, reaction_index, choice_code, reply_text)`에 **"플레이어 선택"**으로 저장하고, 다음 분기 `AdvanceService`가 해당 턴의 선택을 읽어 시드 기반 계산에 반영하면 `game` 결정론을 100% 유지하면서 재현(replay)도 가능해진다.

## 3. 화면 목록 및 사용자 흐름

### 3-1. 화면 목록

| 구분 | 경로 (예시) | 기술 | 주요 기능 |
| --- | --- | --- | --- |
| **게시판 목록** | `/board` | React | 카테고리 탭(전체/자유/공략/질문/엔딩인증), `RECORD` 전용 상권·업종 필터, 검색창(제목/내용/제목+내용/작성자), 정렬(최신/인기/조회/댓글), 공지 상단 고정, 페이지네이션 |
| **게시글 상세** | `/board/posts/{postId}` | React | 본문, `RECORD` 엔딩 요약 카드(`/share/{gameId}` 링크 포함), 좋아요 토글 버튼, 신고 버튼, 수정/삭제(본인만), 댓글/대댓글 목록 및 작성·삭제·신고 |
| **게시글 작성/수정** | `/board/write`, `/board/posts/{postId}/edit` | React | 카테고리 선택, `RECORD` 선택 시 내 종료 게임 목록 드롭다운(미인증 게임만 선택 가능) + 엔딩 카드 미리보기, 제목/본문 입력 |
| **엔딩 공유 페이지** | `/share/{gameId}` | Thymeleaf | 게임 엔딩 요약 + OG 메타태그 + 연결된 `RECORD` 인증글 요약/링크 |
| **관리자 게시판 관리** | `/admin/board` | Thymeleaf | 신고 접수 목록(사유, 대상 유형, 신고 수), 게시글/댓글 숨김(`HIDDEN`) 및 해제, 신고 처리(`RESOLVED`/`DISMISSED`), 공지 고정(`isPinned`) 토글 |

### 3-2. 게임 ↔ 게시판 주요 진입점 (User Flows)

1. **엔딩 화면 → 인증글 쓰기 (가장 핵심 흐름)**
   - 게임 종료(폐업/매각/장수가게) → 엔딩 요약 모달/화면에서 **"커뮤니티에 엔딩 인증하기"** 버튼 클릭
   - `/board/write?category=RECORD&gameId={gameId}` 로 이동 → 카테고리와 게임이 자동 선택되고 엔딩 요약 카드가 프리필됨 → 후기만 적고 등록.
2. **랭킹 → 인증글 보기**
   - 랭킹 테이블(`/rankings`)에서 각 순위 행에 해당 게임의 활성 `RECORD` 글이 존재하면 **"인증글"** 배지/아이콘 표시 → 클릭 시 `/board/posts/{postId}`로 이동.
3. **홈 → 인기글/최신 인증글 미리보기**
   - 홈 화면(`/`)의 "오늘의 랭킹 미리보기" 옆에 **"사장님 커뮤니티 인기글"**(상위 3~5건) 섹션 배치 → 클릭 시 게시글 상세로 이동, "더보기"로 `/board` 이동.
4. **게시글 상세(`RECORD`) → 엔딩 공유 페이지**
   - `RECORD` 글 상단의 엔딩 요약 카드에 **"공유 카드 보기"** 버튼 배치 → `/share/{gameId}`로 이동.

## 4. 사용자 게시판 화면: React vs Thymeleaf 판단

### 결론: **사용자 화면은 React + REST, 관리자 및 공유 페이지는 Thymeleaf** (메인 기본안 지지)

| 기준 | 안 A: React + REST (추천) | 안 B: Thymeleaf 서버 렌더링 |
| --- | --- | --- |
| **기존 아키텍처 정합성** | `DESIGN.md` 14장 기준(게임·랭킹=React, 관리자·공유=Thymeleaf)과 100% 일치. 단일 SPA 내 자연스러운 화면 전환 | 게임(React)과 게시판(Thymeleaf)이 별도 페이지로 뚝 끊겨 UX 이질감 발생 |
| **게스트 인증 연동** | 프론트엔드가 `localStorage`의 `X-Guest-Token`을 API 헤더에 그대로 실어 보내면 됨 | Thymeleaf 폼/링크는 커스텀 헤더(`X-Guest-Token`)를 자동 전송할 수 없어, 게스트 쿠키·세션 브릿지를 별도 구현해야 함 |
| **Spring MVC 평가 대비** | `@RestController` REST API 설계, `@Valid`, `@ControllerAdvice` 예외 처리 + **관리자(`/admin/board`)와 `/share/{gameId}`에서 Thymeleaf 폼/PRG/BindingResult를 이미 시연 가능** | 사용자 화면까지 Thymeleaf를 쓰면 MVC 비중은 늘지만 API/React 연동 일관성과 개발 속도가 저하됨 |
| **데모·포트폴리오 완성도** | 모달/토스트/비동기 좋아요·댓글/게임 내 원클릭 이동 등 현대적 웹 서비스 UX 구현 용이 | 페이지 전체 새로고침 위주 |

**평가 방어 논리 (발표 시 강조 포인트)**:
- "사용자 서비스(게임·랭킹·커뮤니티)는 React SPA + REST API로 분리해 API 계약 기반의 백엔드 설계와 `X-Guest-Token` 인증 일관성을 지켰고, 백오피스(`/admin/board`, `/admin/ingest`)와 SEO/OG가 필요한 공유 페이지(`/share/{gameId}`)는 Spring MVC + Thymeleaf + Spring Security 세션으로 구현해 두 패러다임을 목적에 맞게 모두 활용했습니다."

## 5. 5분 발표 시연 시나리오 대본

발표 목표: **게시판 CRUD 전 항목 + 게임 데이터 연동 + 관리자 Spring MVC(Thymeleaf)**를 5분 안에 빠짐없이 증명한다.

- **0:00 ~ 0:45 | 도입 및 홈 화면 (`/`)**
  - "서울시 실제 상권 데이터로 돌아가는 창업 시뮬레이션과, 플레이 기록이 자연스럽게 이어지는 사장님 커뮤니티를 구현했습니다."
  - 홈 화면의 "오늘의 랭킹"과 "커뮤니티 인기글 미리보기"를 보여주고 커뮤니티(`/board`)로 진입.
- **0:45 ~ 1:45 | 목록 조회, 검색, 필터, 페이징 (`/board`)**
  - 공지글이 최상단에 고정된 것 확인.
  - 정렬을 `최신순 → 인기순 → 조회순`으로 전환하며 페이징 동작 확인.
  - 검색 타입(`제목+내용`, `작성자`)으로 키워드 검색 시연.
  - `엔딩 인증(RECORD)` 탭으로 이동해 **업종(커피-음료) + 상권(망원역)** 필터링 시연("실제 상권 코드로 필터링됩니다").
- **1:45 ~ 2:45 | 게임 연동: 엔딩 → 인증글 작성 (`@Valid` & 중복/권한 검증)**
  - 미리 끝내둔 게임의 엔딩 화면(또는 `/board/write`)에서 **"엔딩 인증글 쓰기"** 클릭.
  - 제목을 비우고 등록 눌러 **Bean Validation(`400 VALIDATION_FAILED`)** 에러 메시지 확인 → 정상 제목/내용 입력 후 등록 (`201 Created`).
  - 생성된 글 상세(`/board/posts/{id}`)에서 스냅샷된 엔딩 카드(생존 분기, 누적 순이익, 업종/상권)와 조회수 증가 확인.
  - **"공유 카드 보기"** 클릭해 Thymeleaf `/share/{gameId}` 페이지와 상호 링크 확인.
- **2:45 ~ 3:45 | 수정(낙관적 락), 댓글/대댓글, 좋아요**
  - 게시글 수정 화면에서 제목 수정 후 저장 → 정상 반영 확인. (발표 멘트로 "동시 수정 시 `version` 기반 낙관적 락 `409`로 충돌을 막습니다" 언급, 또는 테스트 코드/스웨거로 보충).
  - 댓글 작성 → 해당 댓글에 **대댓글(1단계)** 작성 → 좋아요 버튼 클릭(즉시 카운트 +1, 새로고침 후 유지, 재클릭 취소).
- **3:45 ~ 4:35 | 권한 제어 & 신고 → Thymeleaf 관리자 숨김**
  - 다른 사용자(또는 시크릿 창 게스트)로 전환해 방금 쓴 글의 수정/삭제 버튼이 없거나 API 호출 시 `403 FORBIDDEN`이 반환됨을 설명.
  - 해당 글/댓글에 **신고** 접수.
  - `/admin/board` (Thymeleaf + Spring Security 로그인)로 이동 → 신고 목록에서 해당 건 확인 → **숨김 처리(POST → PRG 리다이렉트)** 클릭 → 사용자 화면 새로고침 시 숨김 처리됨을 확인.
- **4:35 ~ 5:00 | 삭제(Soft Delete) 및 마무리**
  - 작성자 계정으로 돌아와 테스트 글 삭제(Soft Delete) 후 목록에서 사라짐을 확인.
  - "Testcontainers 기반 통합 테스트로 CRUD, 403 권한, 409 낙관적 락, 중복 좋아요, 게임 엔딩 검증까지 자동화했습니다."로 마무리.

## 6. 시드/데모 데이터 계획

> **규칙 준수 (`AGENTS.md` 규칙 6)**: 실제 가게 상호는 절대 사용하지 않는다. 상권명("망원역", "성수카페거리", "홍대입구" 등)은 사실 지명으로 사용하되, 가게 이름은 모두 가상 상호를 사용한다.

- **가상 사용자 (`users`)**:
  - `user1`: "망원동김사장" (게스트 → 정회원 전환 가정)
  - `user2`: "성수바리스타"
  - `user3`: "국밥장인박씨"
  - `admin`: 관리자 (`ROLE_ADMIN`)
- **시드 게시글 (`FREE` / `TIP` / `QNA` / `RECORD`, 총 12~15건 — 페이징 2페이지 이상 확인용)**:
  - **공지(`isPinned=true`) 1건**: `[공지] 사장님 커뮤니티 이용 안내 및 엔딩 인증 이벤트`
  - **RECORD(엔딩 인증글) 4건**: 미리 시드된 종료 게임(`ENDED`)과 연결.
    - 예: `"망원역에서 별빛커피로 14분기 장수 가게 달성했습니다!"` (망원역, 커피-음료, `LONG_RUNNING`)
    - 예: `"성수동 소담베이커리 8분기 만에 권리금 받고 매각 성공"` (성수카페거리, 제과점, `SOLD`)
    - 예: `"홍대입구 달빛분식 3분기 폐업 후기... 임대료가 무섭네요"` (홍대입구, 분식, `CLOSED`)
    - 예: `"연남동 푸른초밥 12분기 흑자 유지 비결 공유"` (연남동, 일식, `LONG_RUNNING`)
  - **TIP(공략) 3건**: `"초반 체력 스탯 낮을 때 영업시간 10시간 넘기면 번아웃 옵니다"`, `"커피-음료 업종 원가율 관리 팁"`, `"프랜차이즈 가맹 전환점 수락 vs 거절 기준"`
  - **QNA(질문) 3건**: `"임대료 높은 강남역 vs 유동인구 적은 골목상권 어디가 나을까요?"`, `"직원 2명 뽑는 타이밍 질문"`, `"마케팅 비용 효율이 언제부터 나오나요?"`
  - **FREE(자유) 3건**: `"첫 판에 바로 폐업했는데 묘하게 중독되네요"`, `"오늘의 랭킹 1위분 스탯 궁금합니다"`, `"동네 반응 리뷰 읽는 재미가 쏠쏠하네요"`
- **댓글/대댓글, 좋아요, 신고 시드**:
  - 주요 공략/인증글에 댓글 2~4개 + 대댓글 1~2개 배치.
  - 인기순 정렬 시연이 가능하도록 게시글별 `like_count`(0~25), `view_count`(10~350) 차등 분포.
  - `/admin/board` 시연용 `PENDING` 상태 신고 1~2건 미리 적재.

## 7. 범위 컷 (MVP vs Later)

남은 게임 개발 일정(전환점, 엔딩/랭킹, 카카오 로그인, 배포)을 고려한 현실적 우선순위입니다.

| 구분 | 기말 제출 범위 (MVP) | 이후 확장 범위 (Later) |
| --- | --- | --- |
| **게시판 코어** | 목록(페이징/검색/정렬/필터), 상세(조회수), 작성(`@Valid`), 수정(낙관적 락), 삭제(Soft delete) | 임시저장, 마크다운/리치 에디터 |
| **상호작용** | 댓글 + 1단계 대댓글, 좋아요(`PUT`/`DELETE` 멱등), 게시글/댓글 신고 | 대댓글 알림, 사용자 차단, 조회수 어뷰징 방지(쿠키/IP) |
| **게임 연동** | **(A)** `RECORD` 엔딩 인증글(본인 `ENDED` 게임, 게임당 활성 1개, 스냅샷 필터/정렬), **(B)** `/share/{gameId}` 양방향 연결, 랭킹/엔딩 화면 진입점 | **(C)** 동네 반응(`reactions`) 답글 + 선택 코드 기반 게임 효과 반영 |
| **관리자·운영** | Thymeleaf `/admin/board` (신고 목록, 숨김/해제, 공지 고정 토글) | 금칙어 필터, 자동 블라인드 임계치 설정 |
| **미디어** | 텍스트 + 게임 엔딩 요약 카드 | 이미지 업로드(S3/로컬 스토리지 + 리사이징) |

# 서울 창업 시뮬레이터 (seoul-startup-sim)

서울의 실제 상권 데이터로 돌아가는 창업 커리어 시뮬레이션 웹 게임입니다.

사장님을 만들고 지도에서 서울의 실제 상권을 골라 가게를 열면, 그 상권의 실제 추정매출, 점포 수, 개폐업률, 유동인구와 주변에 실제로 있는 경쟁 점포 데이터로 분기마다 매출과 생존 여부가 계산됩니다. 분기 결산 카드와 전환점 선택을 거쳐 엔딩에 도달하면 오늘의 사장님 랭킹에 올라갑니다.

> 대학 프레임워크 강의 기말과제이자 개인 포트폴리오 프로젝트입니다. (진행 중)

## 핵심 아이디어

- **데이터를 빼면 게임이 성립하지 않는 구조**: 시장 규모, 경쟁자, 위기 확률이 모두 실제 공공데이터에서 나옵니다.
- **실제 시간 흐름을 따라가는 게임**: 게임 시간은 실제 분기 순서(2021년 이후)를 따라가고, 분기가 바뀌면 다음 분기의 실제 데이터가 반영됩니다.
- **재현 가능한 시뮬레이션**: 시드, 플레이어 선택, 데이터 버전이 같으면 결과가 항상 같습니다.
- **서버가 판정하는 랭킹**: 모든 결과를 서버가 계산하므로 클라이언트 조작으로 랭킹 기록을 만들 수 없습니다.

## 게임 흐름

```
사장님 만들기 → 상권과 업종 고르기 → [분기 운영 결정 → 분기 결산 카드 → (전환점)] 반복 → 엔딩 → 랭킹
```

- 1턴 = 1분기. 서울시 상권 데이터의 갱신 주기와 같고, 한 판은 20분 안팎입니다.
- 가입 없이 게스트로 바로 시작하고, 카카오 로그인으로 기록을 이어갈 수 있습니다.

## 백엔드에서 다루는 문제

1. **외부 API 수집 파이프라인**: 속도 제한, 재시도와 백오프, 증분 수집, 수집 이력, 원본과 정규화 데이터 분리
2. **대량 적재**: 상가업소 데이터 적재 방식별 성능 비교 (JPA `saveAll` / JDBC batch / PostgreSQL `COPY`)
3. **위치 기반 조회**: PostGIS 반경 검색, 상권 영역 판정, 공간 인덱스
4. **데이터 버전 관리**: 분기별 갱신이 있어도 진행 중인 게임 결과가 바뀌지 않도록 게임마다 데이터 버전 고정
5. **턴 진행 정합성**: 트랜잭션, 락, DB 제약조건으로 같은 분기가 두 번 진행되는 문제 방지
6. **데이터 기반 이벤트 엔진**: 전환점의 발생 조건과 확률을 DB에 두고 관리자 화면에서 수정
7. **랭킹 배치**: 30분마다 집계, 동점 처리 규칙, 캐시

## 기술 스택 (예정)

| 영역 | 기술 |
| --- | --- |
| Backend | Java, Spring Boot, Spring Data JPA, JdbcTemplate, Spring Security (카카오 OAuth2), Resilience4j, Flyway |
| DB | PostgreSQL + PostGIS |
| Frontend (게임) | React (Vite), 카카오맵 JavaScript SDK |
| 서버 렌더링 화면 (관리자, 공유) | Thymeleaf |
| Test | JUnit 5, WireMock |

## 구조 (예정)

```
[React 게임 화면] ──/api/**──▶ ┐
                               │  Spring Boot
[브라우저] ──/admin/**, /share/**▶│   ├ @RestController  게임 API (JSON)
                               │   ├ @Controller      Thymeleaf (관리자, 공유 페이지)
                               │   ├ @Service         게임 엔진, 수집 로직
                               │   ├ @Repository      PostgreSQL + PostGIS
                               │   └ @Scheduled       외부 데이터 수집기
                               ┘          │
                                          ▼
                     서울 열린데이터광장 / 공공데이터포털 / 카카오
```

게임 요청 처리 중에는 외부 API를 호출하지 않습니다. 외부 데이터는 배치로 수집해 DB에 저장하고, 게임은 DB만 읽습니다.

## 사용 데이터와 출처

| 데이터 | 제공 | 용도 |
| --- | --- | --- |
| 서울시 상권분석서비스 (영역, 추정매출, 점포, 길단위인구, 직장인구) | 서울특별시, 서울신용보증재단 / 서울 열린데이터광장 | 상권 영역, 시장 규모, 개폐업률, 유동인구 |
| 소상공인시장진흥공단 상가(상권)정보 API | 소상공인시장진흥공단 / 공공데이터포털 | 실제 점포 위치와 업종 (경쟁 점포) |
| 카카오맵 API | 카카오 | 지도 표시 |

- 서비스 화면에도 데이터 출처를 표기합니다.

## 환경 변수

API 키는 저장소에 커밋하지 않습니다. `.env.example`을 복사해 `.env`를 만들어 사용합니다.

### 분기 데이터 자동 갱신 (TASK-004E)
- 기본값은 꺼짐: `app.ingest.schedule.enabled=false`. 켜려면 환경 변수 `APP_INGEST_SCHEDULE_ENABLED=true`를 설정합니다.
- 매일 서울 시간 04:00에 매출·점포·유동인구의 최신 ACTIVE 분기 이후부터 현재 분기까지 신규 자료를 확인하고, 제공된 분기만 기존 백필 경로로 적재합니다. 초기 데이터가 없으면 관리자 수동 백필이 먼저 필요합니다.
- 시각은 `app.ingest.schedule.cron`으로 조정합니다. 같은 출처의 중복 적재는 DB의 RUNNING 유일 인덱스로 막습니다. 직장인구 전체 수집과 상권 SHP/메타, 상가 CSV 스냅샷은 관리자 수동 수집 대상입니다.
- 서울 API 수집기는 공통 속도 제한·재시도·서킷 브레이커를 거칩니다. 상가업소는 외부 API가 아닌 로컬 CSV 전체 교체 방식입니다.
- 분기 참조는 버전별로 보존합니다. `/admin/data-versions`에서 삭제 대상 미리보기를 확인하고, 활성·게임 고정·적재 중·현재 상권/점포 참조가 없는 버전만 정리할 수 있습니다.

### 인증 진입점 IP 제한
- `app.security.ip-rate-limit.paths`: POST 제한 경로 목록, 기본 `/api/guest,/api/auth/signup,/api/auth/login`. 아직 없는 인증 경로도 생성되면 같은 독립 필터가 적용됩니다.
- `max-requests=20`, `window-seconds=600`: IP당 설정 경로 전체를 합해 슬라이딩 윈도우 제한합니다. 초과는 공통 `429 RATE_LIMITED` JSON과 Retry-After를 반환합니다.
- `app.security.trust-proxy=false` 기본값에서는 X-Forwarded-For를 무시합니다. 외부에서 프록시를 우회할 수 없고 프록시가 전달 헤더를 덮어쓰도록 구성한 경우에만 켭니다.
- `app.security.ip-rate-limit.max-ips=10000`: 메모리 추적 상한이며 가득 차면 새 IP도 제한합니다. 단일 JVM 정책이므로 다중 인스턴스 배포에는 공유 저장소 제한기를 별도 도입해야 합니다.
